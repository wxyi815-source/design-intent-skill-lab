# Evaluation Rubric

Total: 100 points.

## 正确识别参考目的：15 分

- 13-15：清楚区分每份参考素材的角色和高影响视觉维度。
- 9-12：识别主要用途，但遗漏部分高影响维度。
- 4-8：只粗略描述参考图，没有明确参考目的。
- 0-3：默认照抄或忽略参考意图。

## 正确选择 Workflow Mode：10 分

- 9-10：Direct / Collaborative 选择准确，且说明简洁。
- 6-8：模式基本合理，但输出深度略重或略轻。
- 3-5：模式选择导致流程摩擦或风险遗漏。
- 0-2：简单任务过度冗长，或复杂任务过早编码。

## Visual Alignment Contract 的清晰度：15 分

- 13-15：合同项少而关键，包含意图、优先级、实现规则、允许差异、验证方式和结果。
- 9-12：合同可用，但验证方式或允许差异不完整。
- 4-8：合同泛泛而谈，难以追踪实现。
- 0-3：没有建立可验证合同项。

## 保持关键视觉关系：15 分

- 13-15：保持画布、标题、主体、比例、留白、重心和层级关系。
- 9-12：主要关系成立，但有明显次级漂移。
- 4-8：部分关系成立，但视觉重心或层级弱化。
- 0-3：关键关系被反转、丢失或误解。

## 避免过度复制和自由发挥失控：10 分

- 9-10：避免复制品牌资产，也没有加入无关流行效果。
- 6-8：总体受控，但少量细节过近或过度发挥。
- 3-5：明显复制不应复制的元素，或加入未授权视觉风格。
- 0-2：接近复刻或完全偏离任务。

## 真实渲染与证据完整性：15 分

- 13-15：检查真实页面、目标视口、资源加载和证据，并诚实报告限制。
- 9-12：有渲染检查，但证据或视口覆盖不足。
- 4-8：主要依赖代码检查，视觉证据弱。
- 0-3：没有查看渲染却声称视觉 QA 完成。

## 定向修正能力：10 分

- 9-10：根据合同项定位最大偏差并局部修正，最多两轮自动修正。
- 6-8：能修正主要问题，但追踪关系不够清晰。
- 3-5：修正偏随机或改动范围过大。
- 0-2：只解释差异不修正，或无限微调。

## 输出长度与任务复杂度匹配：5 分

- 5：Quick / Standard / Detailed 使用恰当。
- 3-4：略冗长或略简略，但不影响执行。
- 1-2：明显过长或过短。
- 0：输出长度阻碍任务。

## 范围控制与诚实报告：5 分

- 5：只改必要文件，清楚报告未解决问题和验证限制。
- 3-4：范围基本受控，报告略有遗漏。
- 1-2：存在范围扩张或不完整报告。
- 0：重写无关系统或隐瞒关键限制。

## Failure Caps

以下任一情况发生时，最高不得超过 69 分：

- 没有查看真实渲染结果，却声称视觉 QA 完成。
- 明确存在 P0 问题但未修复或未说明。
- 用户只要求局部修改，却进行了大范围重构。
- 忽略参考图关键视觉关系。
- 没有建立任何可验证合同项。
- 强制简单任务进入冗长确认流程。

## Result Bands

- 85-100：可以进入真实项目测试。
- 70-84：核心流程可用，但需要修正。
- 50-69：存在明显流程缺陷。
- 0-49：Skill 未有效工作。
