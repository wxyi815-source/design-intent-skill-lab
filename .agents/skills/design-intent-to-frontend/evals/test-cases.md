# Test Cases

## Should Trigger

### Case T01
- 用户请求：请根据这张参考图实现一个首页首屏，但不要照抄品牌元素。
- 是否应触发：是
- 测试能力：首页首屏实现
- 期望行为：分析参考意图，建立约束矩阵，输出设计简报后再编码。
- 失败表现：直接复制品牌、文案或未说明哪些内容可改。

### Case T02
- 用户请求：这个页面的标题位置不像参考图，请修正文字区域和换行。
- 是否应触发：是
- 测试能力：文字位置纠偏
- 期望行为：检查标题视觉区域、宽度、基线、换行和留白关系。
- 失败表现：只改一个像素坐标，忽略文字块面积和视觉重心。

### Case T03
- 用户请求：参考这个网页的图文关系和留白，但整体要做出差异。
- 是否应触发：是
- 测试能力：保持参考图关系但形成差异
- 期望行为：保持核心视觉关系，避免复制识别性元素。
- 失败表现：完全照抄或改到关系不再成立。

### Case T04
- 用户请求：把这个桌面设计适配到 390 x 844 移动端。
- 是否应触发：是
- 测试能力：移动端适配
- 期望行为：保留信息优先级和视觉意图，合理重排或裁切。
- 失败表现：只缩小桌面页面导致文字不可读或横向滚动。

### Case T05
- 用户请求：只调整现有页面首屏的图片比例和按钮 hover 状态。
- 是否应触发：是
- 测试能力：已有页面局部修改
- 期望行为：限定范围，只改必要文件并保留技术栈。
- 失败表现：顺手重构整站或改动无关页面。

### Case T06
- 用户请求：请对实现页面和参考图做视觉 QA，列出 P0/P1/P2。
- 是否应触发：是
- 测试能力：视觉 QA
- 期望行为：检查视口、字体、图文比例、对齐和交互状态。
- 失败表现：只说页面能运行，没有分级差异。

## Should Not Trigger

### Case N01
- 用户请求：请润色这段产品介绍文案。
- 是否应触发：否
- 测试能力：纯文案修改
- 期望行为：不调用 Skill，直接处理文案。
- 失败表现：输出设计约束矩阵。

### Case N02
- 用户请求：请设计一个 REST API 的数据库表结构。
- 是否应触发：否
- 测试能力：后端接口
- 期望行为：不调用视觉 Skill。
- 失败表现：讨论视觉重心或参考图。

### Case N03
- 用户请求：修复这个数组排序函数的 bug。
- 是否应触发：否
- 测试能力：普通代码 Bug
- 期望行为：按普通代码调试处理。
- 失败表现：要求视觉 QA。

### Case N04
- 用户请求：解释包豪斯设计理论。
- 是否应触发：否
- 测试能力：设计理论讨论
- 期望行为：给出理论解释，不进入页面实现流程。
- 失败表现：要求目标视口和代码文件。

### Case N05
- 用户请求：配置生产部署环境变量。
- 是否应触发：否
- 测试能力：部署配置
- 期望行为：不调用 Skill。
- 失败表现：生成视觉 QA 报告。

### Case N06
- 用户请求：帮我整理一次用户访谈提纲。
- 是否应触发：否
- 测试能力：用户研究
- 期望行为：不进入前端视觉实现流程。
- 失败表现：创建设计约束矩阵。

## Boundary Cases

### Case B01
- 用户请求：完全照抄这个网站的首页。
- 是否应触发：是
- 测试能力：用户要求完全照抄时如何处理
- 期望行为：拒绝复制受保护识别元素，转为参考布局关系和视觉语言。
- 失败表现：复制品牌资产、文案或独特识别系统。

### Case B02
- 用户请求：我只给一张参考图，帮我做个页面。
- 是否应触发：是
- 测试能力：用户未说明参考目的
- 期望行为：采用保守策略，说明假设，必要时问关键澄清问题。
- 失败表现：随意猜测并大幅自由发挥。

### Case B03
- 用户请求：参考这个页面的感觉，顺便修复登录接口错误。
- 是否应触发：部分触发
- 测试能力：混合视觉与后端任务
- 期望行为：拆分范围，视觉部分使用 Skill，后端部分按普通调试处理。
- 失败表现：把所有任务都纳入视觉 Skill。

### Case B04
- 用户请求：讲讲为什么这个布局看起来更高级，如果需要也可以改页面。
- 是否应触发：视情况
- 测试能力：理论讨论和潜在实现混合
- 期望行为：先确认是否需要页面修改；若修改则触发。
- 失败表现：未确认就改代码，或完全忽略实现需求。

## Input Readiness Cases

### Case I01
- 用户请求：请只实现首页首屏静态布局。参考图 1 主要看左上标题位置和图文比例，不复制品牌、文案和图标。桌面端 1440 x 900，移动端 390 x 844。完成标准是无横向滚动、标题位于首屏偏左上、正文不超过 36rem、不改导航结构。
- 是否应触发：是
- 测试能力：输入完整
- 期望行为：判断为 Ready，不重复提问，整理约束后进入设计简报和实施流程。
- 失败表现：仍要求用户填写完整模板，或重复询问已经说明的信息。

### Case I02
- 用户请求：只调整首页标题位置，参考图主要看左上布局，不改其他元素。
- 是否应触发：是
- 测试能力：输入基本可用
- 期望行为：判断为 Usable with assumptions，说明次级间距、断点和样式延续当前项目，不额外追问并继续执行。
- 失败表现：强迫用户补全所有响应式、素材和动效细节。

### Case I03
- 用户请求：按照这个做首页。
- 是否应触发：是
- 测试能力：只有参考图
- 期望行为：不直接编码；提示用户至少说明主要参考方向；提供构图、字体、留白、色彩、图片、动效等可选项；最多提出 3 个关键问题。
- 失败表现：默认整张图都要严格保持，或抛出长问卷。

### Case I04
- 用户请求：我上传了三张参考图，帮我做一个首屏。
- 是否应触发：是
- 测试能力：多张参考图用途不同
- 期望行为：要求为每张图明确角色，或提供可选择的参考用途；不把三张图混合成模糊风格。
- 失败表现：把冲突参考揉成无法验证的审美描述。

### Case I05
- 用户请求：我喜欢图一那种感觉，但不要做得一模一样，要更像我自己的作品集。
- 是否应触发：是
- 测试能力：用户不会设计术语
- 期望行为：将自然语言转译成结构化约束，提示用户选择喜欢的是构图、留白、文字、颜色、图片关系还是动效，不要求专业术语。
- 失败表现：追问“你想要什么风格”或直接加入作品集专属规则。

### Case I06
- 用户请求：参考图颜色很鲜艳，但当前项目设计系统是低饱和中性色。请参考它的布局做首屏。
- 是否应触发：是
- 测试能力：参考图与项目规则冲突
- 期望行为：指出色彩与项目规则冲突，保留布局关系，按项目优先级处理，只询问真正影响方向的决策。
- 失败表现：直接套用参考图颜色，或因为冲突停止所有工作。

### Case I07
- 用户请求：不用问我，先做一个版本，参考图主要看整体图文关系。
- 是否应触发：是
- 测试能力：用户要求直接开始
- 期望行为：只要不存在结构性阻塞，就使用保守假设继续，并将假设写入设计简报。
- 失败表现：强制用户填写表格，或静默虚构具体品牌、素材和验收标准。

### Case I08
- 用户请求：怎样才能更好地描述网页设计需求？
- 是否应触发：否
- 测试能力：用户只问如何写提示词
- 期望行为：不自动触发实施型 Skill，除非用户明确要用这个 Skill 开始网页任务。
- 失败表现：输出完整设计实施流程，或把 Skill 变成通用提示词教学工具。

## Design Alignment Cases

### Case A01
- 用户请求：参考这张海报式网页首屏，做 demo-site 首页。参考文字排版、配色、字体和画面结构，不需要中心人物。
- 是否应触发：是
- 测试能力：Pre-implementation Visual Plan Check
- 期望行为：编码前明确 canvas strategy、title placement、typography match level、color relationship、visual subject relationship、overlap policy。
- 失败表现：只输出笼统的“参考风格”，没有规划画布、标题、字体和叠压关系。

### Case A02
- 用户请求：参考图看起来有黑色边框，请做得像它。
- 是否应触发：是
- 测试能力：Canvas strategy
- 期望行为：判断黑边可能是截图或展示外场，询问或说明是否应保留；不得默认把网页做成小海报卡片。
- 失败表现：页面主画面过小，四周保留大黑边，不符合网页首屏。

### Case A03
- 用户请求：参考图标题在画面中心，字号很大，行距很紧。
- 是否应触发：是
- 测试能力：Title placement and typography matching
- 期望行为：实现前明确标题居中、视觉质量、行距、字重和大小写；QA 时检查是否仍变成左对齐文本块。
- 失败表现：标题仍按当前页面左侧栏布局实现，或字体过粗、过大、行距不对。

### Case A04
- 用户请求：参考海报式层级，但正文不要压住标题。
- 是否应触发：是
- 测试能力：Overlap policy
- 期望行为：区分允许的视觉层叠和禁止的文字碰撞；QA 中将意外叠压列为 P0。
- 失败表现：小字、按钮或正文与主标题发生不可读叠压。

### Case A05
- 用户请求：第一版不够像参考图，主要问题是画布太小、标题不居中、行距不对。
- 是否应触发：是
- 测试能力：Design Alignment Loop
- 期望行为：将反馈映射到 canvas、title placement、typography、spacing 等维度，做局部修正，不重写无关页面。
- 失败表现：重新自由发挥，或只解释差异不修正。

## Workflow Mode and Contract Cases

### Case W01
- 用户请求：标题位置太低，只调整标题，不改其他内容。
- 是否应触发：是
- 测试能力：简单标题修复
- 期望行为：Direct Execution Mode；Quick output；1-3 条合同项；不要求完整确认；查看真实渲染；只修改必要文件。
- 失败表现：输出完整长篇 Design Brief，要求用户填全模板，重构页面，或没看真实页面就声称完成。

### Case W02
- 用户请求：请参考这张图做首页核心首屏，借鉴构图和留白，但不要完全复制。
- 是否应触发：是
- 测试能力：首页核心首屏
- 期望行为：Collaborative Alignment Mode；Standard 或 Detailed output；Visual Alignment Card；3-8 个关键锚点；确认关键方向；分阶段实现；Visual Alignment Contract；Screenshot Delta Loop。
- 失败表现：直接编码，或只给泛泛风格描述。

### Case W03
- 用户请求：不用确认，先做一个版本。
- 是否应触发：是
- 测试能力：用户要求直接开始
- 期望行为：没有阻塞项时使用保守假设继续；内部建立 Alignment Contract；不强制等待确认；假设写入 brief。
- 失败表现：强制等待确认，或跳过合同和视觉验证。

### Case W04
- 用户请求：计划里标题在左上，但实现后看起来还是偏低。
- 是否应触发：是
- 测试能力：Checklist 正确但实现偏差
- 期望行为：真实截图检查；合同项失败；标记 P0/P1；定向修正容器或锚点；再次渲染；更新状态。
- 失败表现：只解释“可能不准”，没有映射合同项和修正。

### Case W05
- 用户请求：这两种图片裁切都能接受，但感觉不一样。
- 是否应触发：是
- 测试能力：主观设计差异
- 期望行为：停止无限自动微调，标记 Needs user design review，提供两个具体选择及设计影响。
- 失败表现：继续随机裁切或只问“你觉得怎么样？”

### Case W06
- 用户请求：请做视觉 QA，但当前环境无法打开浏览器。
- 是否应触发：是
- 测试能力：无法使用浏览器
- 期望行为：明确 `Visual verification incomplete`；不声称视觉准确；不安装无关依赖；列出需要人工检查的合同项。
- 失败表现：仅凭代码声称完成视觉 QA，或安装新依赖。

### Case W07
- 用户请求：这个页面有复杂首屏、动效和移动端适配，请按参考图实现。
- 是否应触发：是
- 测试能力：复杂页面分阶段实现
- 期望行为：Pass 1 检查构图；构图未通过前不优先制作动效细节；每阶段只修改相关维度。
- 失败表现：一次性堆完所有细节，导致偏差无法追踪。

### Case W08
- 用户请求：只修按钮和文字之间的间距。
- 是否应触发：是
- 测试能力：小任务不应冗长
- 期望行为：Quick output；Direct Execution Mode；简短约束；简短 QA；不输出整页 Alignment Card。
- 失败表现：进入 Collaborative Alignment Mode 或输出完整合同长文。

### Case W09
- 用户请求：三张参考图分别看布局、字体和动效，请做首页首屏。
- 是否应触发：是
- 测试能力：多参考图
- 期望行为：每张图有独立角色；合同项追踪来源；冲突项请求用户确认；不混成模糊风格。
- 失败表现：把多图合并为“高级感”并直接编码。

### Case W10
- 用户请求：保留非对称网格、左侧负空间和主体安全区，标题视觉重心不要超过画面中线。
- 是否应触发：是
- 测试能力：用户有设计基础
- 期望行为：使用专业语言协作，不过度基础化解释，并转成可执行约束与合同项。
- 失败表现：忽略专业术语，或把它们解释成长篇教程。
