# Test Cases

## Should Trigger

### Case T01
- 用户请求：请根据这张参考图实现一个首页首屏，但不要照抄品牌元素。
- 是否应触发：是
- 测试能力：首页首屏实现
- 期望行为：分析参考意图，建立约束矩阵，输出设计简报后再编码。
- 失败表现：直接复制品牌、文案或未说明哪些内容可改。

### Case T02
- 用户请求：这个页面的标题位置不像参考图，请修正文字区域和换行。
- 是否应触发：是
- 测试能力：文字位置纠偏
- 期望行为：检查标题视觉区域、宽度、基线、换行和留白关系。
- 失败表现：只改一个像素坐标，忽略文字块面积和视觉重心。

### Case T03
- 用户请求：参考这个网页的图文关系和留白，但整体要做出差异。
- 是否应触发：是
- 测试能力：保持参考图关系但形成差异
- 期望行为：保持核心视觉关系，避免复制识别性元素。
- 失败表现：完全照抄或改到关系不再成立。

### Case T04
- 用户请求：把这个桌面设计适配到 390 x 844 移动端。
- 是否应触发：是
- 测试能力：移动端适配
- 期望行为：保留信息优先级和视觉意图，合理重排或裁切。
- 失败表现：只缩小桌面页面导致文字不可读或横向滚动。

### Case T05
- 用户请求：只调整现有页面首屏的图片比例和按钮 hover 状态。
- 是否应触发：是
- 测试能力：已有页面局部修改
- 期望行为：限定范围，只改必要文件并保留技术栈。
- 失败表现：顺手重构整站或改动无关页面。

### Case T06
- 用户请求：请对实现页面和参考图做视觉 QA，列出 P0/P1/P2。
- 是否应触发：是
- 测试能力：视觉 QA
- 期望行为：检查视口、字体、图文比例、对齐和交互状态。
- 失败表现：只说页面能运行，没有分级差异。

## Should Not Trigger

### Case N01
- 用户请求：请润色这段产品介绍文案。
- 是否应触发：否
- 测试能力：纯文案修改
- 期望行为：不调用 Skill，直接处理文案。
- 失败表现：输出设计约束矩阵。

### Case N02
- 用户请求：请设计一个 REST API 的数据库表结构。
- 是否应触发：否
- 测试能力：后端接口
- 期望行为：不调用视觉 Skill。
- 失败表现：讨论视觉重心或参考图。

### Case N03
- 用户请求：修复这个数组排序函数的 bug。
- 是否应触发：否
- 测试能力：普通代码 Bug
- 期望行为：按普通代码调试处理。
- 失败表现：要求视觉 QA。

### Case N04
- 用户请求：解释包豪斯设计理论。
- 是否应触发：否
- 测试能力：设计理论讨论
- 期望行为：给出理论解释，不进入页面实现流程。
- 失败表现：要求目标视口和代码文件。

### Case N05
- 用户请求：配置生产部署环境变量。
- 是否应触发：否
- 测试能力：部署配置
- 期望行为：不调用 Skill。
- 失败表现：生成视觉 QA 报告。

### Case N06
- 用户请求：帮我整理一次用户访谈提纲。
- 是否应触发：否
- 测试能力：用户研究
- 期望行为：不进入前端视觉实现流程。
- 失败表现：创建设计约束矩阵。

## Boundary Cases

### Case B01
- 用户请求：完全照抄这个网站的首页。
- 是否应触发：是
- 测试能力：用户要求完全照抄时如何处理
- 期望行为：拒绝复制受保护识别元素，转为参考布局关系和视觉语言。
- 失败表现：复制品牌资产、文案或独特识别系统。

### Case B02
- 用户请求：我只给一张参考图，帮我做个页面。
- 是否应触发：是
- 测试能力：用户未说明参考目的
- 期望行为：采用保守策略，说明假设，必要时问关键澄清问题。
- 失败表现：随意猜测并大幅自由发挥。

### Case B03
- 用户请求：参考这个页面的感觉，顺便修复登录接口错误。
- 是否应触发：部分触发
- 测试能力：混合视觉与后端任务
- 期望行为：拆分范围，视觉部分使用 Skill，后端部分按普通调试处理。
- 失败表现：把所有任务都纳入视觉 Skill。

### Case B04
- 用户请求：讲讲为什么这个布局看起来更高级，如果需要也可以改页面。
- 是否应触发：视情况
- 测试能力：理论讨论和潜在实现混合
- 期望行为：先确认是否需要页面修改；若修改则触发。
- 失败表现：未确认就改代码，或完全忽略实现需求。
