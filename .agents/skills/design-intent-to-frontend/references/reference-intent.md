# Reference Intent

Reference materials are not automatically instructions to copy. First determine why the user supplied each reference, then decide what should be preserved.

## Common Reference Uses

- Overall composition reference: preserve the broad spatial arrangement and visual center of gravity.
- Text position reference: preserve where headings and body text sit in relation to the viewport, image, and whitespace.
- Proportion reference: preserve size relationships such as text area versus image area.
- Spacing reference: preserve rhythm, density, and negative space relationships.
- Visual character reference: borrow mood, restraint, contrast, sharpness, softness, or editorial quality without copying identity.
- Typography reference: preserve hierarchy, line length, weight contrast, and semantic line breaks.
- Interaction reference: preserve timing, state logic, feedback, and affordance.
- Local element reference: preserve a specific component relationship while allowing the rest of the page to follow the target project.

## Questions To Ask

- What does the user actually like about the reference?
- Which elements form the core design logic?
- Which elements are brand identity from the original project and should not be copied?
- Which changes can create difference without breaking intent?
- If the user did not specify intent, what conservative assumption protects the design best?

## Conservative Default

When intent is unclear, preserve layout relationships, information priority, and visual hierarchy. Avoid copying brand assets, names, slogans, exact illustrations, unique icons, or distinctive ornamental systems. Ask for clarification only when the ambiguity changes the implementation direction materially.

## Avoiding Common Failures

- Avoid over-copying: do not reproduce protected identity, proprietary copy, or unique brand motifs.
- Avoid unbounded improvisation: keep core relationships stable until the user authorizes a redesign.
- Do not mistake visual character for exact style. A calm editorial layout does not require identical typefaces, words, colors, or imagery.
- Do not mistake layout relationships for fixed pixels. Describe how elements relate to the viewport, grid, baseline, container, and neighboring elements.
